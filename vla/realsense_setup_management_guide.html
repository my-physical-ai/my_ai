1카메라 인식 & 시리얼 확인

가장 먼저 하는 일. 카메라가 잡히는지, 시리얼 번호가 무엇인지 확인합니다.

🪪
왜 시리얼이 중요할까

시리얼 번호는 카메라의 주민등록번호예요. 카메라가 2대 이상이거나, LeRobot 같은 프로그램에서 특정 카메라를 콕 집어 쓰려면 이 번호가 꼭 필요해요. USB 포트를 바꿔 꽂아도 시리얼은 안 변해요.

🔍연결된 카메라 + 시리얼 한눈에 보기
$ rs-enumerate-devices -s Device Name Serial Number Firmware Version Intel RealSense D456 318122301700 5.17.3.10 Intel RealSense D435 138422072965 5.17.3.10

▶ 연결된 모든 RealSense의 이름·시리얼·펌웨어 버전을 표로 보여줍니다.

  • -s는 short(요약) 모드 — 핵심만 간단히
  • 여기 나오는 시리얼(예: 318122301700)을 그대로 복사해 config에 사용
  • 모델명(D435/D456)으로 어느 카메라가 어느 것인지 구분
📋더 자세한 정보 (센서·옵션까지)
$ rs-enumerate-devices # -s 없이 실행하면 전체 상세

▶ 각 카메라의 지원 해상도, FPS, 센서 종류, 캘리브레이션 정보까지 모두 출력합니다.

  • 어떤 해상도·FPS 조합이 가능한지 확인할 때 사용
  • 출력이 매우 기니 rs-enumerate-devices | less로 넘겨보면 편함
🐍파이썬으로 확인 (conda 환경 점검용)
$ python -c "import pyrealsense2 as rs; \ print([d.get_info(rs.camera_info.serial_number) for d in rs.context().devices])" ['318122301700', '138422072965']

▶ conda 환경 안에서 pyrealsense2가 카메라를 잡는지 확인합니다.

  • 이게 되면 LeRobot 같은 파이썬 프로그램도 카메라를 쓸 수 있음
  • 빈 리스트 []가 나오면 → 권한(udev) 또는 USB 문제
  • ModuleNotFoundError가 나오면 → pip install pyrealsense2 필요
💡 Viewer는 되는데 파이썬만 안 될 때: RealSense Viewer는 시스템에 깔린 프로그램이고, 파이썬은 conda 환경에서 돕니다. Viewer가 돼도 conda 환경에 pyrealsense2가 없으면 파이썬은 실패합니다 — 별개의 층이에요.

2USB 연결 속도 확인

RealSense는 USB3에서만 제대로 작동합니다. 실수로 USB2에 잡히면 화질·프레임이 무너져요.

5000M
USB3 (정상)
깊이+컬러 풀 스트림 OK
480M
USB2 (문제)
해상도·FPS 제한, 에러
~3.2Gbps
USB3 실효 대역폭
여러 대 쓸 때 기준
⚡USB 링크 속도 확인 (가장 중요)
$ lsusb -t | grep -i real # 예시 출력 (Driver=uvcvideo, 5000M 이면 USB3 정상) |__ Port 2: Dev 5, ... Driver=uvcvideo, 5000M

▶ 카메라가 USB2로 잡혔는지 USB3로 잡혔는지 확인합니다.

  • 5000M = USB3, 정상
  • 480M = USB2로 잘못 잡힘 → 케이블 또는 포트 교체 필요
  • 포트를 바꾸거나 케이블을 바꿔가며 5000M이 나오는 조합을 찾기
🌲USB 버스 구조 전체 보기 (여러 대일 때)
$ lsusb -t # 전체 USB 트리 — 어느 카메라가 어느 Bus(컨트롤러)에 있는지

▶ 카메라 2대가 같은 컨트롤러(Bus)를 공유하는지 확인합니다.

  • 서로 다른 Bus 번호에 있으면 → 대역폭을 온전히 나눠 씀 (좋음)
  • 같은 Bus에 몰려 있으면 → 대역폭 경쟁으로 끊길 수 있음
🔌 케이블이 범인일 때가 많습니다. 충전 전용 케이블이나 저품질 케이블은 USB2로 잡히거나 연결이 끊깁니다. RealSense는 반드시 데이터 지원 USB3 케이블을 쓰고, D456 같은 산업용은 정품/인증 케이블을 권장합니다.

3권한 & udev 설정

일반 사용자가 sudo 없이 카메라에 접근하려면 권한 규칙이 필요합니다.

🔑
udev 권한이란

USB 장치는 기본적으로 관리자(root)만 만질 수 있어요. udev 규칙은 "이 카메라(Intel 제품)는 일반 사용자도 쓸 수 있게 열어줘"라고 리눅스에 알려주는 출입증이에요. 이게 없으면 파이썬에서 카메라가 안 잡혀요.

✅권한 규칙이 이미 있는지 확인
$ ls -l /etc/udev/rules.d/ | grep -i realsense -rw-r--r-- 1 root root 10684 ... 99-realsense-libusb.rules

▶ librealsense 설치 시 자동으로 깔리는 권한 규칙이 있는지 봅니다.

  • 99-realsense-libusb.rules가 보이면 → 이미 완료, 추가 작업 불필요
  • 이 규칙이 Intel 벤더 ID(8086)를 가진 모든 RealSense에 접근 권한을 부여
⬇️규칙이 없을 때만 — 공식 규칙 설치
$ sudo wget -O /etc/udev/rules.d/99-realsense-libusb.rules \ https://raw.githubusercontent.com/IntelRealSense/librealsense/master/config/99-realsense-libusb.rules $ sudo udevadm control --reload-rules # 규칙 다시 읽기 $ sudo udevadm trigger # 즉시 적용

▶ 공식 권한 규칙을 내려받고 즉시 적용합니다.

  • 다운로드 후 reload-rules + trigger 두 명령으로 적용
  • 확실히 하려면 카메라 USB를 뽑았다 다시 꽂기
📷 RealSense는 심링크(이름표) udev가 필요 없습니다. LeRobot이 시리얼 번호로 직접 카메라를 찾기 때문이에요. 권한 규칙(99-realsense-libusb.rules)만 있으면 됩니다. 반면 로봇 팔 시리얼 포트나 USB 웹캠은 /dev 번호가 바뀌므로 이름 고정 udev가 필요합니다 — 장치를 "무엇으로 찾느냐"에 따라 갈립니다.

4스트림 확인 (영상 보기)

카메라가 실제로 영상을 내보내는지 눈으로 확인합니다.

📺GUI 뷰어 — 가장 직관적
$ realsense-viewer

▶ 그래픽 창으로 컬러·깊이(depth)·적외선 스트림을 실시간으로 봅니다.

  • 왼쪽 패널에서 카메라별로 Stereo(깊이)/RGB 스트림을 켜고 끔
  • 여러 대 연결 시 상단 "Add Source"로 다른 카메라 추가
  • Info 탭에서 시리얼·펌웨어·USB 타입 확인 가능
🖥️터미널에서 스트림 통계만 (SSH·헤드리스)
$ rs-fw-update -l # 연결 목록 + 펌웨어(다음 섹션과 연결) $ rs-depth # 깊이 스트림을 아스키로 터미널에 표시 (GUI 없이 테스트)

▶ 모니터 없는 서버(헤드리스)에서 카메라가 도는지 확인할 때 사용합니다.

  • rs-depth는 깊이 데이터를 텍스트로 출력 — SSH 환경에서 유용
  • 영상 자체보다 "스트림이 나오는가"를 확인하는 용도
🤖LeRobot에서 카메라 찾기
$ lerobot-find-cameras realsense # 연결된 RealSense의 시리얼과 지원 스펙을 출력

▶ LeRobot이 인식하는 RealSense 목록을 확인합니다.

  • 여기서 시리얼이 뜨면 LeRobot config에 바로 사용 가능
  • 안 뜨면 → pyrealsense2 미설치 또는 권한 문제

5펌웨어 관리

카메라 내부 소프트웨어(펌웨어)를 확인·업데이트합니다. 신중하게 다뤄야 합니다.

🔎현재 펌웨어 버전 확인
$ rs-fw-update -l # 연결된 카메라의 현재 펌웨어 버전 표시 # (rs-enumerate-devices -s 로도 Firmware Version 확인 가능)

▶ 각 카메라의 현재 펌웨어 버전을 확인합니다.

  • 업데이트가 필요한지 판단하는 첫 단계
  • SDK 버전과 펌웨어 버전은 서로 호환되는 짝이 있음
⬆️펌웨어 업데이트 (필요할 때만)
$ rs-fw-update -f <펌웨어파일.bin> # 특정 펌웨어로 업데이트 # 또는 여러 대 중 하나만: -s <시리얼> 옵션 추가 $ rs-fw-update -s 318122301700 -f Signed_Image_UVC_5_17_3_10.bin

▶ 카메라 펌웨어를 지정한 버전으로 업데이트합니다.

  • -s로 특정 시리얼만 골라 업데이트 (여러 대 연결 시 안전)
  • 업데이트 중 절대 USB를 뽑지 말 것 — 카메라가 망가질 수 있음
⚠️ 펌웨어·SDK 업데이트는 신중하게! LeRobot이 쓰는 pyrealsense2 버전과 시스템 SDK/펌웨어가 어긋나면 잘 되던 카메라가 안 잡힐 수 있습니다. 지금 데이터 수집이 잘 되는 환경이라면 함부로 올리지 마세요. Viewer가 "Update Recommended" 팝업을 띄워도, 문제가 없으면 Dismiss로 닫아도 됩니다.

6카메라 2대 이상 운영

여러 RealSense를 동시에 쓸 때 반드시 알아야 할 대역폭 규칙.

상황결과권장
2대를 다른 USB3 컨트롤러에 직결안정적✅ 최선
2대를 같은 USB 허브에 연결대역폭 경쟁·끊김❌ 피하기
depth + RGB 둘 다 풀 스트림 × 2대대역폭 초과 위험⚠️ 해상도↓ 또는 depth off
RGB만 (depth off) × 2대여유 있음✅ VLA 학습용 권장
📊 대역폭 계산: depth 스트림(848×480)은 약 442Mbps를 씁니다. USB3 실효 대역폭(~3.2Gbps)을 여러 대가 나눠 쓰므로, 안 쓰는 depth는 끄는 게 안전합니다. LeRobot은 use_depth를 안 넣으면 자동으로 RGB만 사용합니다.
🔀2대 각각 다른 Bus인지 확인
$ lsusb -t | grep -i real # Bus 번호가 서로 다르면 컨트롤러 분리됨

▶ 두 카메라가 대역폭을 나눠 쓰지 않도록 물리적으로 분리됐는지 확인합니다.

  • Bus 번호가 같으면 → 마더보드의 다른 위치 포트로 옮기기
  • 데스크톱은 뒷면 포트가 보통 별도 컨트롤러에 물려 있음
