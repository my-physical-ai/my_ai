SmolVLA 데모용 수집 시나리오 · 3색 × 60회 = 180회

데모·과제에서 확실히 성공이 목표라면 색당 60회가 안전선입니다. 공식 가이드가 "태스크당 시작점 ~50회"를 권장하고, 색으로 집는 대상이 달라지는 3색은 사실상 3개 태스크라서요. 여기에 수집 품질 관리까지 더해 성공률을 끌어올리는 설계입니다.

🎯 이번 수집의 전체 그림

한 데이터셋 안에 3개의 색 세션을 담습니다. 세션마다 멘트(태스크 문장)는 딱 하나로 고정하고, 그 멘트를 60회 내내 똑같이 사용해요.

총 에피소드 (3색 × 60회) — 데모 성능을 노리는 안전 규모
🎬
영화 촬영에 비유하면 — 색깔별로 "장면(scene)"을 나눠 찍는 거예요. 빨강 장면 60테이크, 파랑 장면 60테이크, 녹색 장면 60테이크. 각 장면의 대사(멘트)는 정해져 있고 테이크마다 똑같이 말합니다. 바뀌는 건 대사가 아니라 배우 위치(블록 위치)예요.

🤔 왜 30회가 아니라 60회인가

데모에서 확실히 성공하려면 회차를 아껴선 안 됩니다. 공식 기준과 실전 사례가 그 이유를 말해줘요.

회차 구성색당총계공식 권장 대비데모 적합성
최소 실습용30회90회약 60%⚠️ 위치·조명 바뀌면 실패 증가
데모 권장 ✅60회180회120%✅ 안전선
여유 있는 구성70회210회140%💪 어려운 조건에도 견고
📖

공식 가이드 기준. SmolVLA 문서는 "자신의 태스크당 시작점으로 약 50 에피소드"를 권장합니다. 3색은 집는 대상이 색마다 달라지므로 사실상 3개의 태스크에 가까워요. 그래서 색당 60회 = 180회가 "시작점"을 여유 있게(약 120%) 채우는 구성입니다.

📈

데이터가 늘수록 성공률이 오릅니다. 한 실전 연구에서 데모를 25 → 50 → 100개로 늘리자 성공률이 약 37% → 60% → 65%로 상승했습니다. 30회 부근은 곡선의 불안정한 저지대이고, 50회부터 성능이 안정되기 시작하며, 60회는 그 위에 여유를 더한 구간이에요.

⚠️

양보다 "일관성"이 더 무섭습니다. 저비용 로봇에서 60개 시연으로 파인튜닝했는데 오히려 성능이 나빠진 사례가 보고됐어요. 원인은 대개 흔들리는 시범·제각각인 조명·실패 데이터 혼입입니다. 그래서 이 문서는 회차뿐 아니라 수집 품질 관리를 함께 강조합니다(아래 체크리스트).

🎯 결론: 데모가 목표면 색당 60회(총 180회)로 시작하세요. 시간이 정말 부족하면 30회로도 파이프라인은 돌아가지만, "확실한 성공"은 보장하기 어렵습니다.

🔤 가장 중요한 규칙 · 멘트는 "언제 고정하고 언제 바꾸나"

SmolVLA는 멘트(single_task)를 카메라 영상과 함께 실제로 읽고 행동을 정합니다. 그래서 멘트를 언제 바꾸느냐가 데이터 품질을 좌우해요.

🔒 멘트를 고정하는 경우

  • 같은 색 블록을 60회 반복할 때 → 멘트 1개로 통일
  • 블록의 위치만 바뀔 때 (왼쪽/가운데/오른쪽)
  • 조명·배경이 조금 달라질 때
  • 즉, "로봇이 하는 행동은 같다" → 멘트 그대로

🔀 멘트를 바꾸는 경우

  • 블록 색이 바뀔 때 (빨강→파랑→녹색)
  • 집는 대상이 달라질 때
  • 넣는 통이 달라질 때
  • 즉, "로봇이 다르게 행동해야 한다" → 멘트 변경
⚠️ 가장 흔한 실수: "다양성을 주려고" 회차마다 멘트를 조금씩 다르게 쓰는 것 (예: "빨강 집어" / "레드 큐브 옮겨" / "블록을 통에"). 이러면 SmolVLA는 이게 다 다른 작업인가? 하고 헷갈립니다. 다양성은 멘트가 아니라 "블록 위치"에서 줍니다.

⌨️ 실제 수집 명령어 (세션별로 3번 실행)

같은 데이터셋(repo_id)에 이어서 3번 녹화합니다. 바뀌는 건 single_task 멘트 하나뿐이에요. 카메라는 수업 표준인 웹캠 3대(타입3) 기준입니다.

① record_red_60.sh — 🔴 빨강 60회
lerobot-record \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM1 \
  --robot.id=my_follower \
  --robot.cameras="{ top:   {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: \"MJPG\"},
       side:  {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30, fourcc: \"MJPG\"},
       wrist: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30, fourcc: \"MJPG\"} }" \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM0 \
  --teleop.id=my_leader \
  --display_data=true \
  --dataset.repo_id=data/three_color_pick \
  --dataset.push_to_hub=false \
  --dataset.num_episodes=60 \
  # ↓ 빨강 세션 멘트 — 60회 내내 이 문장 고정
  --dataset.single_task="Put the red block into the purple bin" \
  --dataset.streaming_encoding=true \
  --dataset.encoder_threads=2
② record_blue_60.sh — 🔵 파랑 60회 (같은 데이터셋에 이어서)
lerobot-record \
  # ... 위와 로봇/카메라 설정 완전히 동일 ...
  --dataset.repo_id=data/three_color_pick \
  # ↑ 같은 데이터셋에 이어서 저장 (resume)
  --dataset.num_episodes=60 \
  # ↓ 멘트만 파랑으로 교체
  --dataset.single_task="Put the blue block into the purple bin" \
  --dataset.streaming_encoding=true \
  --dataset.encoder_threads=2
③ record_green_60.sh — 🟢 녹색 60회 (같은 데이터셋에 이어서)
lerobot-record \
  # ... 위와 로봇/카메라 설정 완전히 동일 ...
  --dataset.repo_id=data/three_color_pick \
  --dataset.num_episodes=60 \
  # ↓ 멘트만 녹색으로 교체
  --dataset.single_task="Put the green block into the purple bin" \
  --dataset.streaming_encoding=true \
  --dataset.encoder_threads=2
📌 왜 같은 repo_id에 이어 담나요? SmolVLA는 하나의 데이터셋 안에 여러 멘트가 섞여 있는 걸 학습합니다. 이렇게 모으면 나중에 "red block"이라 지시하면 빨강을, "green block"이라 지시하면 녹색을 집는 언어로 제어되는 하나의 모델이 완성돼요. 색마다 데이터셋을 쪼개면 이 장점이 사라집니다.

🎮 녹화 중 키보드 조작 (실패는 저장 금지!)

각 세션 60회를 녹화하는 동안 키보드로 흐름을 제어합니다. 특히 실패한 시범은 반드시 삭제하세요.

키동작언제 쓰나
→ 오른쪽이번 에피소드 저장 후 다음으로시범을 깔끔히 성공했을 때
← 왼쪽이번 에피소드 삭제 후 다시 녹화블록을 놓쳤거나 실패했을 때
ESC세션 종료 → 인코딩이 색 60회를 다 채웠을 때
🚫 실패 데이터는 독입니다. 빨강을 집어야 하는데 파랑을 건드렸거나, 통 밖에 떨어뜨린 시범은 ←로 지우세요. "잘못된 시범 + 맞는 멘트" 조합이 데이터에 섞이면, SmolVLA는 멘트와 반대되는 행동을 배웁니다.

✅ 데모 성공률을 높이는 수집 품질 체크리스트

회차만 채운다고 되는 게 아닙니다. 실전에서 "데이터는 많은데 성능이 나빠지는" 실패의 원인은 대부분 품질과 일관성이에요. 데모가 목표라면 아래를 지키세요.

🔒 반드시 고정할 것

  • 카메라 위치·각도 — 수집~데모 내내 동일
  • 조명 — 밝기·방향 일정하게 (커튼·창가 주의)
  • 통(purple bin) 위치 — 크게 옮기지 않기
  • 배경 — 물건 어수선하게 두지 않기

🔀 의도적으로 다양화할 것

  • 블록 시작 위치 — 5곳 이상 골고루
  • 집는 각도 — 매번 똑같이 말고 자연스럽게
  • 접근 경로 — 살짝씩 다른 궤적
  • 단, 다양화는 "장면"에서만 — 멘트는 그대로
🎯

성공한 시범만 저장. 놓치거나 실패한 에피소드는 ←로 즉시 삭제하세요. "실패 시범 + 맞는 멘트"가 섞이면 모델이 멘트와 반대되는 행동을 배웁니다. 데모 실패의 대표 원인이에요.

🖐️

시범은 부드럽고 일관되게. 급하게 홱 움직이거나 멈칫하는 시범이 많으면 모델이 흔들립니다. 같은 리듬으로 천천히, 매 에피소드 비슷한 속도로 시연하세요.

🎥

데모 환경 = 수집 환경. 발표장 조명·카메라·통 위치를 수집 때와 최대한 똑같이 맞추세요. VLA는 학습 때 본 장면과 비슷할수록 잘합니다. 환경이 바뀌면 180회를 모아도 무너질 수 있어요.

🔁 학습 후 부족한 색만 보강. 180회로 학습 → 추론 테스트 → 특정 색(예: 파랑)만 실패율이 높으면 그 색만 20~30회 추가 수집해 재학습하세요. 처음부터 완벽할 필요 없이, "약한 곳을 찾아 메우는" 반복이 가장 효율적입니다.

🧠

학습. lerobot-train --policy.path=lerobot/smolvla_base --dataset.repo_id=data/three_color_pick — 3색 멘트가 섞인 180회 데이터를 한 번에 학습합니다.

🎯

추론. 추론 때 --dataset.single_task="Put the green block into the purple bin"이라고 지시하면 SmolVLA가 초록만 골라 집습니다. 멘트를 바꾸면 집는 색이 바뀌어요 — 이게 언어로 제어되는 VLA의 힘입니다.

📈

보강 루프. 추론 테스트에서 약한 색을 찾아 그 색만 추가 수집 → 재학습. 데모 직전까지 이 루프를 돌리면 성공률이 꾸준히 오릅니다.

📚 근거: SmolVLA 공식 문서는 파인튜닝 시작점으로 태스크당 약 50 에피소드를 권장하며, 도입하는 각 변형(예: 블록 위치)마다 충분한 시연을 반복하라고 명시합니다(논문 데이터셋: 5개 위치 × 반복 = 50회). 본 시나리오는 색으로 대상이 달라지는 3색을 사실상 3개 태스크로 보고 색당 60회 × (위치 5곳 × 12회) = 180회로 구성했습니다. 실전 연구에서 데모 수를 25→50→100개로 늘리자 성공률이 약 37%→60%→65%로 상승한 사례가 있어, 데모 목표에는 50회 이상이 안전합니다. 한편 약 60개 시연으로도 성능이 나빠진 실패 사례가 보고되는데, 원인은 대개 흔들리는 시범·조명 불일치·실패 데이터 혼입으로, 회차뿐 아니라 수집 품질 관리가 필수임을 보여줍니다.
