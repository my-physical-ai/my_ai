⬡ OVERVIEW

lerobot-edit-dataset이란?

📚
초등학생도 이해하는 비유

데이터셋이 공책 묶음이라면, lerobot-edit-dataset은 편집 가위와 풀 세트다.
나쁜 페이지(실패 에피소드)는 잘라내고, 좋은 공책끼리 붙이고, 제목(task)도 고치고, 목차(메타데이터)도 새로 만들 수 있다.

💡 Dataset v3 구조(many episodes per file + metadata 경계 관리)이기에 가능한 기능이다. v2에서는 이런 편집 도구가 없었다.

🔧 공통 파라미터 구조

기본 명령어 구조
lerobot-edit-dataset \
  --repo_id=local/{입력_데이터셋_이름} \      # 수정할 데이터셋
  --root=/path/to/input/dataset \          # 입력 폴더 (로컬 저장 시 필수)
  --new_repo_id=local/{출력_데이터셋_이름} \  # 결과물 이름 (생략 시 in-place 수정)
  --new_root=/path/to/output/dataset \    # 결과물 폴더 (생략 시 in-place)
  --operation.type={operation 종류} \      # info/delete_episodes/merge/split 등
  --operation.{추가_파라미터}=... \         # operation별 추가 파라미터
  --push_to_hub=false                        # 로컬 작업 시 필수
파라미터설명필수
--repo_id입력 데이터셋 식별자. local/이름 형식필수
--root입력 데이터셋 로컬 폴더 경로필수*
--new_repo_id출력 데이터셋 식별자. 생략 시 in-place 수정 (원본 backup 생성)선택
--new_root출력 데이터셋 로컬 폴더 경로. 생략 시 in-place선택
--operation.type수행할 작업 종류필수
--push_to_hubHuggingFace Hub 업로드 여부기본 false
💡
in-place vs 새 폴더 new_repo_id/new_root를 지정하면 원본은 유지되고 결과물이 새 폴더에 생성됨.
생략하면 원본이 수정되고 자동으로 backup이 생성됨. 실습에서는 항상 new_root를 지정해 원본을 보호하는 것을 권장한다.

🔗 merge — 여러 데이터셋 병합
demo + hil 합본, oversampling, 다중 수집 통합
📚
이해하기 쉽게!

여러 권의 공책을 하나의 큰 바인더에 합치는 것과 같다.
공책 A(demo)와 공책 B(hil)를 합쳐서 새로운 공책 C(trainmix)를 만든다.

💡 같은 데이터셋을 여러 번 나열하면 oversampling(비중 높이기) 효과가 있다.

📌 기본 사용 — demo + hil 합본 (trainmix)

demo + hil 병합 → trainmix 생성HIL 재학습 핵심
lerobot-edit-dataset \
  --new_repo_id=local/so101_doll_box_trainmix_v1 \
  --new_root=/home/zeta/lerobot_datasets/doll_box_trainmix_v1 \
  --operation.type=merge \
  --operation.repo_ids="['local/so101_doll_box_demo_v1','local/so101_doll_box_hil_v1']" \
  --operation.roots="['/home/zeta/lerobot_datasets/doll_box_demo_v1','/home/zeta/lerobot_datasets/doll_box_hil_v1']" \
  --push_to_hub=false

# 결과: demo(50개) + hil(10개) = trainmix(60개 에피소드)
🚨
Catastrophic Forgetting 방지 — 반드시 합본으로 학습 HIL만 단독 학습 → 기존에 잘 하던 정상 동작을 잊어버림 (파국적 망각)
반드시 demo + hil 합본(trainmix)으로 학습해야 기존 능력 유지 + 교정 능력 추가

⬡ STEP 4
4
✂️ split — 데이터셋 분할
학습/검증 분리, 대용량 분할, 조건별 나누기
📖
이해하기 쉽게!

두꺼운 공책 1권을 "연습장(train)"과 "시험지(validation)"로 나누는 것과 같다.
AI가 연습장으로 공부하고, 시험지로 잘 배웠는지 평가한다.

80/20 학습-검증 분할권장 비율
lerobot-edit-dataset \
  --repo_id=local/so101_doll_box_demo_v1 \
  --root=/home/zeta/lerobot_datasets/doll_box_demo_v1 \
  --new_repo_id=local/so101_doll_box_split \
  --new_root=/home/zeta/lerobot_datasets/doll_box_split \
  --operation.type=split \
  --operation.splits='{"train": 0.8, "validation": 0.2}'
  --push_to_hub=false

# 50개 에피소드 기준: train=40개, validation=10개로 분리됨
💡
언제 split을 사용하나? 데이터셋이 100개 이상 에피소드가 될 때 학습/검증을 분리해 과적합(overfitting)을 감지하는 데 사용한다.
50개 이하의 소규모 수집에서는 분할 없이 전체로 학습하는 것이 일반적이다.

시험 점수 평균을 계산했는데 나쁜 점수를 삭제하거나 새 점수를 추가했다면 평균을 다시 계산해야 한다.
AI 학습도 데이터의 평균/표준편차로 정규화하므로, 편집 후 반드시 재계산이 필요하다.

💡 merge 후 학습 시 통계 불일치로 학습 성능이 저하될 수 있으므로 권장한다.

병합 후 통계 재계산 (기본)merge 후 권장
lerobot-edit-dataset \
  --repo_id=local/so101_doll_box_trainmix_v1 \
  --root=/home/zeta/lerobot_datasets/doll_box_trainmix_v1 \
  --operation.type=recompute_stats
  --push_to_hub=false

# 완료 후 통계 파일이 갱신됨
# → meta/info.json 내 statistics 섹션 업데이트
영상/이미지 제외하고 빠르게 재계산
lerobot-edit-dataset \

📋 7가지 operation 한눈에 요약

Operation역할언제 사용
info 데이터셋 현황 조회 (에피소드 수, 프레임, FPS, 크기) 편집 전 항상 먼저 실행. 인덱스 범위 확인
delete_episodes 특정 에피소드 삭제. 인덱스 0부터 시작 실패 에피소드 제거, oversampling 전 분리
merge 여러 데이터셋 병합. 같은 것 여러 번 나열하면 oversampling demo+hil 합본, 다중 수집 통합, 비중 강화
split 비율로 분할. train/validation 분리 에피소드 100개+ 대용량, 과적합 모니터링
remove_feature 카메라/feature 채널 제거 카메라 교체, 불필요한 센서 데이터 정리
modify_tasks task 문장 수정 오타 수정, 더 명확한 task 설명으로 개선
recompute_stats 정규화 통계 재계산 merge/delete 후 반드시 실행 권장
✅
황금 규칙: 편집 전후 반드시 info로 확인 편집 전: 에피소드 수, 인덱스 범위 확인
편집 후: 에피소드 수가 예상대로 변경되었는지 확인
merge 후: recompute_stats 실행으로 정규화 통계 갱신
