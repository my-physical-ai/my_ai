phase 주석 실전
— 개수·카메라·그리퍼값

phase를 몇 개까지 늘려도 되는지, 카메라가 3개일 땐 어떻게 하는지, 그리퍼 숫자로 어떻게 경계를 정확히 잡는지. Qwen3-VL 주석을 실제로 적용할 때 부딪히는 문제들을 초등학생 눈높이로 풀었습니다.

🔢 phase는 몇 개까지 늘려도 될까?

"행동을 두 배 이상 많이 나눠도 되나요?" — 됩니다. 하지만 조건이 있어요.

▲ phase 개수와 성능의 관계 — 너무 적어도, 너무 많아도 나쁨

✅ 좋은 늘리기 vs ❌ 나쁜 늘리기

✅
좋은 늘리기시각적으로 뚜렷한 세분화

grasp(잡기) 하나를 → grasp_open(벌린 채 접근) → grasp_close(닫는 중) → grasp_confirm(잡힘 확인)으로 나누는 건 OK. 각 단계가 영상에서 눈으로 구분되니까 Qwen3가 나눌 수 있어요.

❌
나쁜 늘리기눈에 안 보이는 구분

grasp_light(약하게) vs grasp_firm(강하게)처럼 나누면 안 돼요. 힘의 세기는 영상만 봐선 구분이 안 돼요. Qwen3가 판단할 근거가 없으니 이름표가 엉망이 됩니다.

🔑
판단 기준 한 문장: "이 단계를 Qwen3가 영상만 보고 명확히 구분할 수 있는가? 그리고 이 단계에 충분한 데이터가 있는가?" 둘 다 Yes면 늘려도 됩니다. 전체를 균일하게 두 배로 늘리기보다 정밀함이 필요한 단계(잡기·정렬)만 세분화하세요.

📷 한 에피소드에 영상이 3개면?

탑·사이드·손목 3개 카메라. 이건 서로 다른 장면이 아니라, 같은 순간을 3방향에서 찍은 것이에요.

🎥
핵심 전제

3개 카메라는 똑같은 시간축을 공유해요. 0초의 탑캠·사이드캠·손목캠은 모두 같은 순간이에요. 그러니 phase도 그 순간엔 하나예요 (0초 = 다가가기). 카메라가 3개라고 phase가 3개가 되는 게 아니에요.

▲ 3개 카메라가 같은 시간축 공유 → phase는 프레임당 하나

🛠️ 처리하는 세 가지 방법

방법방식장점단점
1. 대표 1개가장 잘 보이는 카메라만 Qwen3에간단·빠름가림 있을 때 놓칠 수
2. 여러 뷰여러 카메라 동시에 Qwen3에정확느림·복잡
3. 상태값 보조그리퍼·관절 숫자 활용가장 정확신호 정의 필요
🗂️
데이터 구조 핵심: 카메라는 images.top·images.side·images.wrist로 나뉘어 저장되지만, phase_id(또는 task_index)는 카메라별이 아니라 프레임당 하나만 붙어요. 카메라는 phase를 판단하는 재료일 뿐, phase 자체는 시간축에 하나입니다.

🤖 그리퍼 값으로 경계 "보정"하기

"탑 카메라로도 알 수 있지 않나요?" — 맞아요. 그런데 그리퍼 숫자가 더 정확할 때가 있어요.

🔢 "그리퍼 개폐 값"이 뭐예요?

SO-ARM101은 매 순간 자기 관절 상태를 숫자로 기록해요. 그중 하나가 그리퍼(집게)가 얼마나 벌어졌는지를 나타내는 숫자예요. 데이터의 observation.state 안에 이미 들어있어요.

그리퍼 값을 프레임마다 쭉 보면, grasp(잡기)가 언제 시작됐는지 숫자로 정확히 보여요:

frame시간그리퍼 값무슨 일
280.93초5아직 벌어짐 (다가가는 중)
290.97초8벌어짐
301.00초15닫히기 시작! ← grasp 시작
311.03초40닫히는 중
331.10초98완전히 닫힘

숫자만 봐도 "frame 30에서 닫히기 시작 = 여기가 grasp 시작"이라고 딱 알 수 있죠. 이렇게 숫자로 phase 경계를 정확히 찍는 것이 "보정"이에요.

📷 카메라 vs 🔢 그리퍼 숫자

▲ 카메라는 큰 흐름, 그리퍼 숫자는 정확한 경계 — 둘을 합치면 최선

🎯 phase별 가장 정확한 판단 방법

phase가장 정확한 판단 방법
approach (다가가기)📷 카메라 (그리퍼 값 안 변함)
grasp (잡기)🔢 그리퍼 값 (닫히기 시작 = 정의)
lift (들기)🔢 팔 높이 값 (올라감)
move (옮기기)📷 카메라 / 팔 위치 값
place (놓기)🔢 그리퍼 값 (열리기 시작 = 정의)
💡
왜 그리퍼 숫자가 더 정확한가: ① 탑캠은 잡는 순간 손이 물체를 가려서 애매해요. 그리퍼 값은 가림과 무관. ② grasp·place는 그리퍼 개폐가 정의 그 자체라 숫자로 보는 게 가장 정확해요.

⚙️ 실제 적용 — 간단한 규칙

# 복잡하게 생각 안 해도 됩니다. 이런 규칙만 넣으면 끝

그리퍼 값이 (벌림→닫힘) 바뀌는 프레임
   → 그 지점을 grasp 시작으로 확정

그리퍼 값이 (닫힘→벌림) 바뀌는 프레임
   → 그 지점을 place 시작으로 확정

나머지 단계(approach, move…)
   → Qwen3 카메라 판단에 맡김
🎓
정리: Qwen3가 카메라로 대략 나눈 다음, grasp/place의 정확한 경계만 그리퍼 숫자로 다시 확인해 살짝 조정하는 게 "보정"이에요. 다만 이건 정밀도를 높이는 선택 사항 — 처음엔 카메라(Qwen3)만으로도 충분히 돌아가요. 정확도가 아쉬울 때 추가하세요.

📚 근거: phase 분해 시 시각적으로 구분 가능한 경계여야 VLM(Qwen3-VL) 자동 주석이 신뢰성 있게 동작. 멀티뷰 데이터는 동일 타임스탬프를 공유하므로 phase 라벨은 프레임 단위 단일 값(LeRobot 데이터 구조상 카메라별이 아닌 프레임당 task_index/feature). 그리퍼 개폐·관절 상태 등 proprioception 신호는 접촉·파지 이벤트 경계 검출에 영상보다 정밀하며, VLM 판단과 상태 기반 규칙을 결합하는 하이브리드 주석이 실무에서 권장됨.
